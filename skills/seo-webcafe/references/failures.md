# 失败模式与标准动作

## 掉登录 / 看不到「今日剩 N」

用户在浏览器里可能没有登录，或登录过期。动作：`await task.handOff()`，告诉用户「请在打开的浏览器里登录 Web.Cafe，然后告诉我继续」。
不要尝试代填账号密码、不要改用游客额度硬跑（游客只有 10 分/天，重活跑不动）。

## 额度不足 / 已满

页面出现 402、429、`quota`、`day_cap`、或「今日额度已用完」：立即停止后续查询，把已经拿到的结果整理成回答，并告诉用户：
- 每日额度北京时间 8:00 重置（VIP 500/天）；
- 游客额度按 IP 只有 10/天；
- 提示可去 `/wallet/` 了解积分（但不要替用户购买）。
不要换另一个工具「凑」同一份数据——那是浪费额度的行为。

## 目标页面抓取失败（On Page 体检 / 页面军师 / AdSense）

页面会显示具体原因，例如：
- `目标不是 HTML 页面（Content-Type: text/plain）`
- `目标页面返回 HTTP 522`
- 上游超时、限流

动作：原文记录错误，换一个可公开访问的 HTML 页面重试一次；仍失败就报告失败，不反复重试。失败通常不扣费（页面会写「不扣」）。

## 页面结构可能已变（改版）

当按页面文件的「等待完成」条件等到超时，且 `#error` 为空、`#result` 也没有内容：
1. 先 `page.reload()` 再等一次；
2. 仍不行就截图 + 输出当前 DOM 关键文本，回答用户「页面可能改版，本次未取到数据」，并建议下次更新技能；
3. 不要改用内部接口或猜测数据。

## 结果为空但没报错

空结果也要如实说。区分三种：
- 真的没有数据（如域名从未被 Archive 抓取、Spam 库未收录）；
- 权限不够（数据服务需要购买权限，页面会提示）；
- 条件写错（关键词非英文、域名格式错、CSV 列不对）。

页面自己的 `meta.reason` / 提示文字优先于你的推测。

## 超时与慢

- KD/SERP 首次 5–15 秒；`adsense` 可到 60 秒+；`mine`/`translate` 30 秒–2 分钟。
- 等待条件用「状态栏消失 + 关键文本出现」，不要用固定 sleep。
- 长时间无响应时先 `page.reload()`，不要直接再点一次按钮（可能重复扣费）。

## 浏览器被用户接管

ego-browser 检测到用户操作会停止任务。动作：停止脚本、不要重试、等用户回来再继续同一个 TaskSpace。

## 与官方 API 的边界

- 不生成、不索要 `wc_mcp_` 令牌；不调用 `api/v1/*`、`*/api/*` 内部接口批量取数（robots.txt 禁止）。
- 如果用户主动要求 API 路线，那是另一件事，告诉对方本技能只覆盖网页版路线。
